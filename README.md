AFF定例資料作成　引き継ぎ用説明書
========================================
対象ソース：card_AFF_document_creation（Streamlit / Python）
作成目的：アプリの利用方法・入力仕様・計算方法・保守箇所を後任者に伝えるための資料
※本書は提供されたソースコードに基づく。実際の業務データを用いた動作確認は未実施。

【1. アプリの概要】
デイリーレポート、コストレポート、AFコードマスタ、必要に応じてAF申込・発行実績データを読み込み、AFF定例資料に貼り付ける16:9のPNG画像を生成する。
生成対象：①全体実績 ②還元サイト実績 ③非還元サイト実績 ④AF実績（AF申込・発行の両方が必要） ⑤媒体別分析（選択した1サイト）。媒体別分析はゲージ・進捗テキスト・グラフの個別パーツ画像も生成する。
画像は画面でプレビューでき、個別PNGまたは「AFF定例資料画像.zip」で一括保存できる。ExcelやPowerPointの完成資料を出力するアプリではない。

【2. 操作手順】
1）サイドバー「AFコードマスタをアップロード」に最新版xlsxを指定する。コード上、マスタ未アップロードの場合は st.stop() で処理が停止する。画面内にBoxへのマスタリンクがある。
2）「デイリーレポート」と「コストレポート」をアップロードする。各ファイルはパスワード保護を解除し、対象シートだけを残し、数式を値に変換しておく。読み込むのはExcelのアクティブシート。
3）AF実績画像も必要なら「AF申込実績データ」と「AF発行実績データ」を両方アップロードする。
4）「集計期間」を指定する。初期値は読み込んだデータの日付の最小日～最大日。開始日・終了日を含む集計。
5）「対象月」（1～12）と「締め日」（例：5/27）を確認する。これは主として画像上の表記であり、集計対象日は別途「集計期間」で決まる。
6）画面に出る全体実績・還元サイト実績・非還元サイト実績・AF実績（条件を満たす場合）を確認し、PNGを保存する。
7）「媒体別分析」でサイトを選択し、必要なら全体画像と3種類のパーツ画像を保存する。サイト一覧に「モッピー」があれば初期選択される。
8）画面末尾の「全画像をまとめてダウンロード」で生成済み画像をZIP保存する。ZIPには媒体別パーツ画像も含む。

【3. 入力ファイル仕様】
■ AFコードマスタ（xlsx、必須）
・1行目を見出しとみなし、A列2行目以降をAFコードとして取得。
・前後空白を削除し、数値の末尾「.0」を取り除いて文字列照合。空欄と重複コードは除外。
・一致したAFコード列だけがAF申込／発行実績の集計対象となる。
・コード上の read_af_master() はファイルパスという引数名だが、実際にはアップロードファイルを渡している。

■ デイリーレポート（xlsx）
・アクティブシートを openpyxl(data_only=True) で読み込む。数式セルにキャッシュ値がないと空欄になるため、値貼り付け推奨。
・結合セルは解除し、結合範囲に左上セルの値を埋める（メモリ上で処理）。
・D列：サイト名、T列：ディテール、U列以降：日別数値、3行目：日付見出し。
・3行目でExcel日付型として認識できる列のみ日付列に採用。日付列がないと読み込み失敗。
・ポイントサイト合計KPI：12～15行目。比較サイト合計KPI：15～19行目。※15行目は両範囲に含まれる。コードが明示的に両範囲を抽出しているため、元ファイルの行配置変更時は要確認。
・明細：32行目以降。サイト名は前行から前方補完。サイト名・ディテールが空欄の行は除外。
・重要なディテール表記：「Daily Target (Initiative)」「Actual」「CT」。文字列完全一致で抽出。
・値は数値化できない場合0として扱う。

■ コストレポート（xlsx）
・アクティブシート、3行目以降を読み込む。A列の日付が空欄／TOTAL／日付変換不可の行は除外。
・A列：日付
・C列：申込_Forecast、D列：申込_実績
・K列：発行_Forecast、L列：発行_実績
・Q列：目標承認率、R列：承認率
・T列：Forecastコスト、U列：発行コスト
・Y列：目標CPA、Z列：発行CPA
・数値変換不可・空欄は0として扱う。列の増減・順番変更に弱い固定列参照。

■ AF申込実績／AF発行実績（xlsx、AF実績画像を作る場合に両方必要）
・1行目：B列以降にAFコード、A列：日付（YYYYMMDD形式）、2行目以降：実績値。
・マスタ掲載のAFコードと一致した列のみ集計。合致する列がない場合は空の集計データになる。
・日付が変換できない行は除外、実績値が数値化できないセルは0。
・AFコードは前後空白と末尾「.0」を正規化して比較する。

【4. 集計ロジック】
■ 全体実績
・全体CV＝ポイントサイト合計「Actual」＋比較サイト合計「Actual」。
・全体目標＝両サイト合計「Daily Target (Initiative)」の合計。
・全体CV達成率＝全体CV÷全体目標。還元／非還元も同様に各Actual÷各Target。
・Forecastコスト＝コストレポートT列の期間合計。実績コスト＝U列の期間合計。
・COST比率＝実績コスト÷Forecastコスト。
・承認率・目標承認率＝それぞれR列・Q列の期間内「単純平均」。加重平均ではない。
・申込CPA＝期間発行コスト合計÷申込実績合計。想定申込CPA＝Forecastコスト合計÷申込Forecast合計。
・発行CPA・目標CPA＝Z列・Y列の期間内「単純平均」。期間合計コスト÷期間合計発行数とは異なる点に注意。
・0除算時は safe_div() により0。
・下段グラフ：発行Forecast／発行実績の棒グラフとForecastコスト／発行コストの折れ線（右軸）。

■ 還元サイト／非還元サイト
・それぞれデイリーレポートの合計行からTarget、Actualを取得し、達成率＝Actual÷Target。
・下段に日別Target・Actualの棒グラフ。

■ AF実績
・AF発生＝AF申込実績データの対象AFコード・対象期間の総和。
・AF承認＝AF発行実績データの対象AFコード・対象期間の総和。
・申込Forecast＝コストレポートC列の期間合計、発行Forecast＝K列の期間合計。
・AF発生目標＝申込Forecast×0.9、AF承認目標＝発行Forecast×0.9。
・AF発生目標対比＝AF発生÷AF発生目標、AF承認目標対比＝AF承認÷AF承認目標。
・AF発生の想定CPA＝Forecastコスト÷（申込Forecast×0.9）。実績CPA＝発行コスト÷AF発生。
・AF承認の想定CPA＝Forecastコスト÷発行Forecast。実績CPA＝発行コスト÷AF承認。
・CPA想定比＝想定CPA÷実績CPA（通常の実績÷想定とは逆方向）。
・コードコメントにはAF目標を「デイリーレポートのポイント＋比較サイトの目標」と記載した箇所があるが、実装では引数 total_target_cv を使わず、コストレポートのForecast×0.9を使用。仕様確認を推奨。
・AF画像の下段グラフはコストレポートの発行Forecast・発行実績とForecastコスト・発行コストを使用し、AF申込／発行実績の日別値ではない。

■ 媒体別分析
・デイリーレポート32行目以降の明細から、選択サイト名と「Daily Target (Initiative)」「Actual」「CT」を完全一致で抽出。
・期間Target／Actualを合計、達成率＝Actual÷Target。
・日別Target／Actualを棒グラフ、CTを右軸の折れ線で表示。
・パーツ別PNGは元の16:9キャンバスと同じ位置に必要部分だけを描き、その他は白背景。画像をトリミングした小サイズのパーツではない。

【5. 出力ファイル】
・全体実績.png
・還元サイト実績.png
・非還元サイト実績.png
・AF実績.png（AF申込・発行実績の両方が読み込めた場合）
・媒体別分析_＜サイト名＞.png
・＜サイト名＞_ゲージ.png
・＜サイト名＞_進捗.png
・＜サイト名＞_グラフ.png
・AFF定例資料画像.zip（上記の生成済み画像を格納）
・画像はMatplotlibによる16:9、figsize=(16,9)、dpi=120のPNG。保存画像の表示文字は日本語フォント環境に依存する。

【6. システム構成・必要ライブラリ】
・Python、Streamlit、pandas、openpyxl、matplotlib。
・標準ライブラリ：io、zipfile、datetime、pathlib。
・日本語フォント：ソースと同じ階層の fonts/NotoSansJP-Regular.ttf があれば優先。なければ環境にある Noto Sans CJK JP／Noto Sans JP／IPAexGothic／IPAGothic／Yu Gothic／Meiryo 等を探索し、最後はsans-serifにフォールバック。フォントが存在しない場合、画像中の日本語が文字化け・豆腐表示になる可能性がある。
・Streamlit Cloudで運用する場合はrequirements.txtに必要パッケージを記載し、フォントの配置も確認。

【7. 保守時に確認する関数】
・read_daily_report()：デイリーレポートの固定列・固定行と結合セル解除。
・read_cost_report()：コストレポートの固定列参照。
・read_af_master()／normalize_af_code()：AFコードマスタ読み込みと照合用正規化。
・read_af_result_file()／sum_af_result()：AF実績の列選別・期間集計。
・create_kpi_values()：全体KPIの計算。
・create_pointsite_values()／create_comparesite_values()：サイト区分別KPI。
・create_af_overall_values()：AF実績の目標・CPA計算。
・create_media_values()／create_media_chart_df()：媒体別KPI・グラフデータ。
・create_summary_image()／create_pointsite_image()／create_comparesite_image()／create_af_overall_image()／create_media_image()：画像描画。
・create_media_gauge_part_image()／create_media_progress_part_image()／create_media_chart_part_image()：媒体別パーツ描画。
・render_image_block()／render_zip_download()：ダウンロードUI。
・FONT_* 定数：画像の文字サイズ。create_header()、draw_gauge()：共通ヘッダー・達成率ゲージ。

【8. 注意点・既知の確認事項】
1）AFコードマスタは必須。マスタだけアップロードしても画像は作成されない。全体・媒体別の画像生成にはデイリー＋コストの両方が必要。
2）Excelはアクティブシート参照。シートが複数ある場合、意図しないシートを読む可能性がある。
3）数式は data_only=True で取得されるため、値のキャッシュがないと0・欠損扱いになる。アップロード前の値貼り付けを徹底する。
4）デイリーレポートの合計抽出範囲はポイント12～15行、比較15～19行で重複している。テンプレート変更時は特に確認。
5）AF目標のコメントと実装に不一致あり（実装はForecast×90%）。業務定義を確認してから変更する。
6）承認率・発行CPAは日別単純平均。期間全体の加重値と一致しない場合がある。
7）AF実績下段の「実績」はAF実績データそのものではなくコストレポートの発行実績を描画している。
8）達成率ゲージの色表示は0～200%に制限するが、数値ラベルは実際の達成率を表示する。
9）日付選択は各入力ファイルの最小～最大日を使うため、期間が長い場合は意図した月だけに絞る。
10）媒体別画像のサイト名がファイル名に入る。ファイル名に使用できない文字がサイト名に含まれる場合は保存先環境で注意。
11）データが空、または期間内に該当行がない場合、0表示・空グラフや例外の可能性がある。画面のエラーを確認。
12）ファイル読込エラーはサイドバーに表示される。失敗時は列配置、日付形式、パスワード、シート、値貼り付けの有無を確認。
13）ソースコード内のBoxリンクはマスタ入手先。Boxの共有URL・権限が変更された場合は画面内リンクも更新する。

【9. 引き継ぎ時の動作確認チェック】
□ 最新のAFコードマスタを取得し、A列2行目以降のコードを確認した。
□ デイリー／コストの対象シートだけを残し、パスワード・数式を解除した。
□ デイリーの3行目U列以降の日付、D列サイト名、T列ディテールを確認した。
□ コストのA/C/D/K/L/Q/R/T/U/Y/Z列の値と日付を確認した。
□ 集計期間・対象月・締め日を正しく指定した。
□ 全体CV・目標・コスト・CPAをExcelの手計算と突き合わせた。
□ 還元／非還元のTarget・Actualを確認した。
□ AF申込／発行のコード一致・対象期間・合計値を確認した。
□ AFの90%目標とCPA想定比の業務定義を確認した。
□ 媒体別のサイト選択・CT線グラフ・パーツ画像を確認した。
□ 日本語文字が欠けず、PNGのレイアウトが崩れていない。
□ 個別PNGと一括ZIPを保存・展開できる。
